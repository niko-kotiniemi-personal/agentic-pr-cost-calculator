# Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build task 1.20 of `add-pr-cost-calculator`: the glossary, `docs/glossary.md`; the rewording of the specs, the change's proposal, design and tasks and the other Markdown pages to it, `CLAUDE.md` among them; `tests/test_glossary.py`; the script that lists each changed line that differs by more than a word to avoid replaced with its term, with its output kept as evidence; and the threat model's test resolving a cited scenario only in `openspec/specs/` and the active changes.

**Architecture:** The glossary is one Markdown page with a table per topic. A test parses each row into a term, its meaning and its words to avoid, checks the entries against each other, and then reads the prose of every tracked Markdown file that it does not leave as written, failing on each word to avoid with the file, the line and the term to use. The titles that accepted records quote are found by matching the records' quotations against the specs' titles; `tests/test_decisions.py`, which already compares the records and the IDs with the base commit, also fails when such a title that the base's specs held is gone from the specs. A standard-library script compares a pull request's changed lines with its base and lists every change that is more than a word to avoid replaced with its term, `CLAUDE.md`'s first.

**Tech Stack:** Python 3.11 standard library, pytest, git.

**Spec:** `openspec/changes/add-pr-cost-calculator/specs/project-standards/spec.md` ("The specs and pages use the glossary's words", "Each term is defined once"), design decision 14 and its risks, task 1.20 of the same change, DR-164 and the record that DR-238 replaced, and the threats T90 and T94.

## Global Constraints

- The tool supports Python 3.11 and every later release, with the standard library only; tests may use pytest and PyYAML, which `requirements-dev.txt` pins, and the script uses the standard library alone.
- Tests never use the network (DR-090). The comparison with the base commit reads only the clone's own objects.
- A rewording never changes what a text requires (T94): a requirement, a scenario, `CLAUDE.md`, a threat's answer or residual, the README's statements of what opting in records and publishes, and the pages that adopters act on say after it what they said before. Where a replacement would change that, the line keeps its words and the pull request says why.
- Records keep their words: no file under `docs/decisions/` changes, and a requirement's or a scenario's title that an accepted record quotes keeps its words, wherever it appears.
- A word given as code keeps its spelling, since the test never reads inline code or fenced code blocks (T90).
- The glossary describes and never steers (DR-238): a meaning never narrows a rule in `CLAUDE.md`, a requirement or a scenario that uses the word, and where they differ, those hold.
- Every number written in the pages, the commit messages, the comments or the pull request is computed in the session that writes it.

## The grammar the test reads

`docs/glossary.md`:

```markdown
# Glossary

The words that the specs and pages use, each with its meaning and the words to avoid for it. ...

## The tool and its parts

| Term | Meaning | Words to avoid |
|---|---|---|
| the tool | What this repository builds and releases: the capture step, the report, and the files that adopters copy to use them. | the calculator, the product |
| hook | Claude Code's way of running a command at an event of a session. | |
```

- A topic is a `##` heading followed by one table whose header is `| Term | Meaning | Words to avoid |`. Every other line under a topic is a problem, so that a row the test cannot read is never passed over.
- A row gives one term, its meaning, and its words to avoid separated by commas, or an empty cell.
- The prose before the first topic is read like any page. In the glossary, the test reads every column but the words to avoid, which it reads only as the list.
- A word to avoid is matched as a whole word in any case, and also with "s" or "es" added, so that a plural fails too: the threat model's `ledger changes` is the plural of a listed word. This adds to what design decision 14 says, and the decision is updated in the same pull request.

### Task 2: The wording test and the quoted titles, test first

- In `tests/test_decisions.py`, `title_problems(root: Path, *bases: str) -> tuple[list[str], int]`: each title that a base's specs hold and an accepted record quotes, and that the specs no longer hold, naming the record and the title, and how many quoted titles were compared.
