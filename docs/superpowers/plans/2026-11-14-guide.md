# The guide by concern, and the checks that hold it: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build tasks 1.28, 1.29 and 1.30 of `add-pr-cost-calculator`: the guide, `docs/patterns.md`, written from the assessment of 2026-11-12, with the tests that hold R209, R210, R219 to R222 and R226; the checks that this repository tracks no switch, no ledger file and no reusable workflow before their tasks (R223, R229); and the guide's checks against the base commit and the tasks (R227, R228, R231), with the attribute check of R134 for the guide and `CLAUDE.md`.

**Architecture:** The pages are Markdown, checked by pytest. `tests/test_roadmap.py` keeps the readings of links and hidden text, now taking the texts that they read as an argument, and extends them to hosts, split hosts, addresses, commit IDs, links into `vendor/` and `.claude/skills/`, and `|`, with its own list of names that only look like hosts. A new `tests/test_guide.py` reads the guide's opening, sections, entries and fields, and holds where it says the project stands; it reads links and hidden text with the roadmap's readings, Rests on with the backlog's (`REST`, `holders`, `holder_of`, `records`, `tasks`) and Held by with the threat model's (`index`, `citation_problems`), compares with the base commits that `base_commits` in `tests/test_decisions.py` gives, as the backlog's history does, and checks attributes with `attribute_problems`. R223 and R229 go to `tests/test_repository.py`, reading the tasks with the roadmap's `tasks`. `scripts/rewording.py` lists the guide's changes right after those to `CLAUDE.md`.

**Tech Stack:** Python 3.11 standard library, pytest, PyYAML for the workflows, git.

**Spec:** `openspec/changes/add-pr-cost-calculator/specs/project-standards/spec.md` (R134, R209, R210, R219 to R223, R226 to R229, R231), design decision 12 in `openspec/changes/add-pr-cost-calculator/design.md`, records DR-231 to DR-241, and the assessment's comment on pull request 28 that says where each finding goes.

## Global Constraints

- No test uses the network. The synthetic trees are git repositories made in `tmp_path`, with the session's `GIT_` variables removed, and a base is a commit that `refs/remotes/origin/main` names, as in `tests/test_backlog.py`.
- The guide holds to R221: printable ASCII and line feeds, no `<`, `&`, backslash, `]:` or `|`, no `$` or `~` outside inline code, no host, address, commit ID, `@`, image, `owner/repo` or code block, and links only to tracked files outside `vendor/` and `.claude/skills/`.
- The guide never states what the tool does: an entry cites the requirement or the rule of `CLAUDE.md` that it rests on (DR-232, DR-237).
- A gap names only the item that the assessment homed it in, now the backlog item of the same name (B-021, B-022, B-007, B-002), B-007 for the ledger and price table shaped for one provider, and B-004 for the field that says how hard a record is to reverse, as design decision 12 gives them. No other agreed item gains a gap (DR-239).
- No figure goes into the guide, a commit message or the pull request's text unless it was computed in this session and pasted from the output.
- Each check is shown to fail on a synthetic tree into which its defect is planted, and a check that examined nothing fails.
- Nothing private: the guide is written from the assessment that pull request 28 already holds.

## Review Focus

- A name that reads as a host but is a tracked file's path, at the root or in a path, in prose or in inline code, passes; a sentence that ends with emphasis, as `*word*.` does, is no split host.
- Under Security, Privacy, Identity and credentials, and Supply chain and releases, every record that a principle knowingly accepted names gives the owner as its decider, and every item that a gap names is `Planned` or `In progress`, as the requirement's text says, which is stricter than its scenarios. A record that the change decided, such as DR-112 or DR-126, cannot stand there: the entry is a gap or designed instead.
- R228 reads the files changed between the base's tree and HEAD's, a rename as a removal and an addition; in CI the base is the pull request's base and HEAD the merge commit.
- R231 knows an entry by its heading, so that a renamed entry comes to name each of its gaps anew.
- R227 reads a task as ticked in the active change or in an archived one, and the items under Now from the roadmap's index lines.
